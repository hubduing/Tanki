# Тест-план «Танчиков»

Документ описывает **фактически работающую** систему тестирования и её соответствие
разделу 6 PLAN.md. Все утверждения проверены запуском и чтением файлов тестов.

## 1. Уровни тестирования

| Уровень | Что проверяет | Чем | Где |
|---|---|---|---|
| Юнит | Чистая логика без времени, DOM и рендера | Vitest, окружение `node` | `tests/unit/` |
| Симуляция | Мир, прокрученный на N фиксированных шагов без графики | Vitest со сценариями и ботами | `tests/sim/` |
| Ручной | Ощущения, баланс, звук, UI, масштабирование | Чек-лист приёмки (PLAN.md, приложение Г) | браузер |

Настройка Vitest находится в `vite.config.ts`: `test.include: ['tests/**/*.test.ts']`,
`test.environment: 'node'`. Отдельного `vitest.config.ts` нет.

На момент написания `pnpm test` даёт **18 файлов, 140 тестов, все зелёные**.
Каталог `tests/sim/` содержит, кроме перечисленных ниже, служебные файлы с префиксом `_`
(`_diag*.test.ts`, `_exp*.test.ts`) — это диагностические прогоны с выводом в консоль:
они попадают в общий прогон, но не проверяют утверждений, а только печатают отчёты.
Их состав меняется по ходу работы, поэтому точный список здесь не фиксируется.

### Замечание о симуляциях

`tests/sim/balance.test.ts` и `tests/sim/playability.test.ts` **печатают отчёты, но почти
не проверяют результаты**. `balance.test.ts` требует лишь `files.length === 12` и соблюдение
лимита врагов; `playability.test.ts` — тоже только `files.length === 12`, число побед
выводится в консоль и не проверяется. На фактическом прогоне бот-защитник не проходит
ни одного из 12 уровней (0 побед), а прогон «игрок стоит» заканчивается поражением на всех
уровнях за 9–42 секунды. Это не отказ теста, а необъявленный порог: автоматической проверки
проходимости уровней (приложение Г, «все встроенные уровни проходятся до победы») в наборе нет.

## 4. Команды запуска

Сверено с `package.json`:

| Команда | Что делает |
|---|---|
| `pnpm test` | `vitest run` — полный набор: 18 файлов, 140 тестов |
| `pnpm test:watch` | `vitest` в режиме наблюдения |
| `pnpm check:levels` | `vitest run tests/unit/levels.test.ts` — валидация всех `public/levels/*.json` (14 тестов) |
| `pnpm typecheck` | `tsc --noEmit` |
| `pnpm build` | `tsc --noEmit && vite build` — проверка типов, затем сборка в `dist/` |
| `pnpm dev` | `vite` — дев-сервер на `http://127.0.0.1:5173` |
| `pnpm preview` | `vite preview` — просмотр собранной версии |

Состояние на момент написания: `pnpm test` — зелёный (140 тестов), `pnpm check:levels` —
зелёный (14/14), `pnpm typecheck` — **падает**: служебные файлы в `tests/sim/` (например,
`_diag2.test.ts`, `_diag3.test.ts`, `_exp*.test.ts`) содержат неиспользуемые импорты
и переменные, а `tsconfig.json` включает каталог `tests`, поэтому `tsc --noEmit` сообщает
`TS6133`. Следствие: `pnpm build` тоже завершается ошибкой, пока эти файлы на месте.
Список таких файлов меняется по ходу работы; чтобы снять ошибку, достаточно удалить их
или отключить `noUnusedLocals`/`noUnusedParameters` для `tests`.

## 5. Что проверяется вручную

Автотестами не закрываются:

- **Ощущения управления.** Плавность движения, поведение выравнивания на 8 px, отсутствие
  застреваний в узких проходах и на стыках тайлов (риск R1). Тесты проверяют отдельные случаи,
  но не общее ощущение.
- **Баланс сложности.** Насколько уровни проходимы человеком, темп волн, честность ИИ,
  ценность бонусов (риск R4). Симуляции дают отчёт, но порога проходимости в тестах нет.
- **Звук.** Процедурная музыка и сигналы: разблокировка после первого действия пользователя
  (риск R9), громкость, отсутствие щелчков, соответствие события звуку.
- **Интерфейс.** Меню, экраны загрузки, паузы и итогов, подсказка управления в начале уровня,
  читаемость шрифта, анимации.
- **Масштабирование в браузере.** Целочисленное масштабирование при разных размерах окна,
  отсутствие размытия, поведение при окне меньше логического размера. Юнит-тест
  `computeIntegerScale` проверяет только арифметику коэффициента.
- **Реальная производительность в браузере.** Частота логики не ниже 58 шагов/с и рендера
  не ниже 58 кадров/с на 10-минутном прогоне (приложение Г). `perf.test.ts` меряет только
  время шага логики в Node, без рендера и без DOM.
- **Полный чек-лист приёмки** (PLAN.md, приложение Г) — целиком относится к ручной проверке.
