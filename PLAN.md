## 1. Цель и рамки

**Цель v1.** Браузерная игра в духе классических «Танчиков»: один игрок защищает базу, уничтожает волны врагов, проходит последовательность уровней, получает очки и бонусы, видит рекорды.

**Входит в объём v1**

- Полный игровой цикл: меню → уровень → пауза → итоги уровня → игра окончена → рестарт.
- 8–12 уровней, описанных данными, без правки кода при добавлении уровня.
- Один тип танка игрока с 4 ступенями развития (базовая + 3 улучшения), 4 типа врагов, 6 типов бонусов.
- Тайлы: кирпич (разрушаемый поквадрантно), сталь, вода, лес, лёд.
- Звук и музыка в минимальном объёме, сохранение рекордов и прогресса.

**Не входит в объём v1 (бэклог M10)**

Кооператив на одном экране, сетевой режим, редактор уровней, мобильное управление, достижения, таблицы лидеров онлайн, локализация.

**Главный архитектурный принцип.** Логика игры не знает о вводе, рендере и звуке. Ввод превращается в команды, рендер читает состояние, звук получает события. Логика детерминирована: при одинаковом вводе и одном seed получается одинаковый результат. Это даёт тестируемость без браузера, ускоряет отладку баланса и оставляет открытой дорогу к сети.

## 2. Принятые решения и альтернативы

Решения приняты по умолчанию, чтобы план был исполним. Любое можно отменить — см. раздел 10.

| № | Решение | Почему | Альтернатива | Когда пересматривать |
|---|---|---|---|---|
| D1 | Платформа: браузер, HTML5 Canvas 2D | Нулевая установка, мгновенная проверка, достаточно для 2D-пиксель-арта | Godot, Unity, Pygame | Если понадобятся мобильные сборки или тяжёлые эффекты |
| D2 | TypeScript + Vite + Vitest | Типы ловят ошибки в геометрии и состояниях; Vitest даёт тесты чистой логики | Чистый JS без сборки | Если нужен запуск «открыл файл и играешь» без сборки |
| D3 | Рендер: Canvas 2D, логическое разрешение 256×224, целочисленное масштабирование, сглаживание выключено | Классический вид, чёткие пиксели, предсказуемая геометрия | WebGL, спрайтовый движок | Если объектов станет на порядок больше |
| D4 | Игровой цикл: фиксированный шаг 60 Гц с аккумулятором, fixed-point координаты, рендер без интерполяции | Одинаковая скорость на 60/120/144 Гц; пиксель-арт не должен «плыть», дробные пиксели за тик представлены точно | Переменный шаг | Никогда для этой игры |
| D5 | Детерминизм: seeded RNG и фиксированный порядок обновления | Воспроизводимые баги и тесты, честный баланс | Math.random | Никогда |
| D6 | Уровни и баланс — JSON-файлы, загружаемые отдельно от сборки | Изменение данных не требует пересборки приложения; встроенные файлы проходят валидатор и тесты | Константы в коде | Никогда |
| D7 | Аудио: WebAudio; сначала процедурные сигналы, позже сэмплы | Не требует ассетов на старте; запуск после первого ввода | Готовые файлы сразу | При переходе к полировке |
| D8 | Сохранение: localStorage с номером версии схемы | Просто, достаточно для рекордов и прогресса | IndexedDB | Если появятся реплеи и большие данные |
| D9 | Тесты: Vitest для логики + headless-симуляция мира без рендера | Правила проверяются быстро и без браузера | Только ручное тестирование | Никогда |
| D10 | Один игрок в v1, но ввод и сущности проектируются под второго | Кооп — самое вероятное расширение | Сразу два игрока | При старте M10 |
| D11 | Графика: процедурные пиксель-спрайты в коде (`src/render/sprites.ts`), без внешних файлов; меню и экраны — крупный жирный моноширинный шрифт с обводкой и анимацией | Не требует ассетов, сразу видно в браузере, легко править в коде | Готовые PNG-спрайты и webfont | При переходе к полировке M9 или если понадобятся сложные анимации |

## 3. Архитектура

### 3.1 Слои

```
┌───────────────────────────────────────────────┐
│ UI: меню, HUD, экраны итогов                  │
├───────────────────────────────────────────────┤
│ Машина состояний: Меню → Игра → Пауза → Итоги │
├───────────────────────────────────────────────┤
│ Логика (World): сущности, движение, коллизии, │
│ правила уровня, спавн, счёт                   │
├──────────────┬────────────────────────────────┤
│ Ввод         │ Рендер                         │
│ (команды)    │ (Canvas, спрайты, эффекты)     │
├──────────────┴────────────────────────────────┤
│ Ресурсы: уровни, спрайты, звуки               │
├───────────────────────────────────────────────┤
│ Хранилище: рекорды, прогресс                  │
└───────────────────────────────────────────────┘
```

Зависимости направлены внутрь: логика не импортирует рендер, ввод и аудио. Обмен — через команды (внутрь) и события (наружу).

### 3.2 Модули и ответственность

| Модуль | Ответственность | Не делает |
|---|---|---|
| Ядро цикла | Фиксированный шаг, аккумулятор, ограничение догоняющих кадров, пауза времени | Не знает про танки |
| Машина состояний | Текущее состояние, переходы, вход/выход состояния | Не хранит игровые данные |
| Ввод | Клавиши → команды, буфер нажатий, повтор клавиш | Не двигает танки |
| Мир (World) | Хранит карту и сущности, выполняет шаг обновления | Не рисует |
| Уровень | Загрузка, разбор, валидация, создание стартовой сцены | Не содержит правил боя |
| Сущности | Танк, пуля, тайл, база, бонус, эффект | Не управляют друг другом напрямую |
| Коллизии | AABB по сетке и между сущностями, подшаги для быстрых пуль | Не решает, что значит попадание |
| Правила | Что происходит при попадании, гибели, разрушении базы, конце уровня | Не знают о рендере |
| ИИ | Поведение врагов: направления, огонь, реакция на препятствия | Не рисует и не звучит |
| Спавн | Очередь врагов, точки появления, лимит на поле, анимация появления | Не решает судьбу уровня |
| Рендер | Карта, спрайты, HUD, эффекты, масштабирование | Не меняет состояние |
| Аудио | Реакция на события, микс, запуск после первого ввода | Не влияет на логику |
| Хранилище | Рекорды, прогресс, версия схемы, миграции | Не знает о сущностях |
| Конфиг | Числа баланса, типы врагов, бонусы, палитра | Не содержит логики |

### 3.3 Геометрия (уточнение к черновику архитектуры)

В первом черновике было сказано, что танк занимает 2×2 клетки. Это неверно и здесь исправлено.

| Величина | Значение | Пояснение |
|---|---|---|
| Логический экран | 256×224 px | Классическое соотношение, удобно для HUD справа |
| Игровое поле | 13×13 тайлов по 16 px = 208×208 px, начало в (8, 8) | Поле — сетка, она же структура ускорения коллизий |
| Танк | 16×16 px = ровно 1 тайл | Позиция хранится в fixed-point; при рендере и проверке сеточного выравнивания используется целочисленная пиксельная проекция |
| Кирпич | Тайл 16×16 делится на 4 квадранта 8×8 | Разрушение поквадрантное, как в оригинале |
| Пуля | 4×4 px | Летит по центру ствола |
| Шаг выравнивания для поворота | 8 px | Танк поворачивает, только если совмещён с полутайлом |
| База | 2×2 тайла по центру нижней части поля | Состояние «цела / разрушена» |

Выравнивание по 8 px — ключ к ощущению оригинала и одновременно главный источник багов «застревания». Координаты хранятся в fixed-point с точностью 1/256 px. При шаге 60 Гц скорости из таблицы дают целое число fixed-point единиц за тик (30/45/60/90 px/с = 128/192/256/384 единиц), поэтому остаток не отбрасывается. Коллизии проверяются в fixed-point, отрисовка округляется до целого пикселя. Поворот разрешён при выравнивании координаты поперечной оси по сетке 8 px; ввод нового направления плавно доводит танк до ближайшей линии перед поворотом, не меняя скорость вдоль текущего направления. Максимальная коррекция поперечной координаты — половина тайла (8 px); если до линии больше, поворот ждёт следующего допустимого окна. Это ограничение должно быть подтверждено тестами проходов и поворотов.

### 3.4 Порядок обновления одного шага

1. Прочитать ввод и превратить в команды игрока.
2. Обновить таймеры: неуязвимость, заморозка, лопата, время жизни бонусов.
3. Обновить ИИ: выбрать направление и решить, стрелять ли.
4. Двинуть танки с проверкой коллизий по сетке и между танками.
5. Двинуть пули подшагами, разрешить попадания (тайл, танк, база, граница).
6. Применить последствия: разрушение тайлов, гибель, очки, выпадение бонуса.
7. Обработать спавн: появление новых врагов, анимация, лимит на поле.
8. Проверить условия завершения: база разрушена, игрок потерял все жизни, враги кончились.
9. Сформировать события для звука и эффектов.
10. Отрисовать кадр (вне логического шага, при рендере).

Порядок фиксирован и не меняется: сначала движение, потом пули, потом последствия. Иначе появляются «призрачные» попадания и проезды сквозь стены.

### 3.5 Состояния и переходы

| Состояние | Вход | Выход |
|---|---|---|
| Загрузка | Старт приложения | Ресурсы готовы → Меню; ошибка загрузки уровня → сообщение об ошибке и возврат в меню |
| Меню | Из загрузки, из итогов | Старт игры → Игра; выбор уровня → Игра |
| Игра | Из меню, из паузы | Пауза, Итоги уровня, Игра окончена |
| Пауза | Из игры | Игра; Меню (текущий забег завершается, рекорд сохраняется, незавершённый уровень не считается пройденным) |
| Итоги уровня | Уровень пройден | Следующий уровень → Игра; финал → Игра окончена |
| Игра окончена | База разрушена или кончились жизни | Меню, рестарт |

Правило: переходы только через машину состояний. Глобальных флагов «идёт ли игра» в коде быть не должно.

### 3.6 Данные сущностей

| Сущность | Поля |
|---|---|
| Танк | Позиция, направление, скорость, здоровье, ступень улучшения, признак «игрок/враг», тип врага, таймер перезарядки, таймер неуязвимости, признак заморозки |
| Пуля | Позиция, направление, скорость, владелец, признак «пробивает сталь», признак «уже попала» |
| Тайл | Тип, координаты тайла, для кирпича — маска целых квадрантов |
| База | Позиция 2×2, состояние, таймер стальной защиты |
| Бонус | Тип, позиция, время жизни, мигание перед исчезновением |
| Эффект | Тип, позиция, таймер (взрыв, вспышка появления, всплывающие очки) |

### 3.7 Числовые ориентиры баланса

Значения — стартовая точка, все живут в конфиге и правятся без пересборки.

| Параметр | Значение |
|---|---|
| Скорость игрока | 60 px/с на всех ступенях; меняется только скорость пули, как описано в приложении В |
| Скорость врагов | 30–60 px/с по типу |
| Скорость пули | Игрок: 180 / 240 / 300 px/с по уровням 0 / 1 / 2–3; враги: 180–300 px/с по типу |
| Перезарядка игрока | 0,25–0,5 с |
| Интервал стрельбы врага | 0,5–2,0 с по типу |
| Пули игрока на поле | 1 одновременно на уровнях улучшения 0–1; 2 одновременно на уровнях 2–3; лимит относится только к пулям игрока |
| Пули одного врага на поле | 1 одновременно; лимит применяется отдельно к каждому врагу, общий максимум для четырёх врагов — 4 |
| Максимум врагов на поле | 4 занятых слота: враг считается с начала анимации появления; очередь уровня в лимит не входит |
| Врагов на уровень | Ровно 20 в v1; состав по типам задаётся для каждого уровня |
| Жизни игрока | 3 |
| Неуязвимость после респауна | ~3 с |
| Заморозка врагов (бонус «таймер») | ~10 с |
| Стальная база (бонус «лопата») | ~15 с |
| Время жизни бонуса на карте | ~15 с с миганием в конце |

## 6. Тест-план

### 6.1 Уровни тестирования

| Уровень | Что проверяет | Чем |
|---|---|---|
| Юнит | Чистая логика без времени и рендера | Автотесты |
| Симуляция | Мир, прокрученный на N шагов без графики | Автотесты со сценариями |
| Ручной | Ощущения, баланс, звук, UI | Чек-лист приёмки |

### 6.2 Юнит-тесты

- Разбор уровня: корректный файл, неверная длина строки, неизвестный символ, отсутствие базы, база не 2×2, недопустимая позиция точки появления.
- Коллизии: танк против каждого типа тайла; танк против границы; пуля против тайла; пуля против танка; пуля против пули.
- Разрушение кирпича: попадание в каждый из четырёх квадрантов по отдельности и по границе квадрантов.
- Выравнивание: поворот возможен только при совмещении с полутайлом; поворот в проходе шириной в один тайл.
- Перезарядка и лимит пуль; лимит врагов на поле; очередь спавна.
- Очки: за каждый тип врага; за звезду, подобранную на максимальном уровне улучшения.
- Таймеры: истечение неуязвимости, заморозки, лопаты, времени жизни бонуса.
- Детерминизм: одинаковый seed и ввод дают одинаковое состояние мира.
- Хранилище: чтение и запись, миграция версии схемы, устойчивость к повреждённым данным.

### 6.3 Сценарные симуляции

- «Игрок стоит на месте»: враги не могут разрушить базу мгновенно, уровень не зависает.
- «Игрок ничего не делает»: игра корректно заканчивается поражением.
- «Игрок уничтожает всех»: уровень завершается победой ровно один раз.
- «Все враги застряли»: за N шагов каждый враг сменил направление хотя бы раз.
- «Стрельба в упор»: пуля не пролетает сквозь стену на максимальной скорости.
- «Наложение бонусов»: одновременные заморозка, щит и стальная база корректно завершаются.
- Длинный прогон: 10 000 фиксированных шагов с активной очередью спавна и постоянной стрельбой; проверить, что активные враги не превышают 4, пули соблюдают свои лимиты, временные сущности (пули, эффекты, бонусы) удаляются после завершения, а число сущностей не растёт монотонно и остаётся в заданных пределах.

## Приложение А. Формат файла уровня

Уровень — внешний JSON-файл в каталоге уровней: метаданные и сетка 13×13. Приложение загружает данные уровней отдельно от основного бандла, поэтому замена или добавление уровня не требует пересборки; при ошибке загрузки показывается диагностическое сообщение. Источник истины для базы — сетка: четыре `E` обязаны образовывать один квадрат 2×2; отдельная позиция базы в метаданных не хранится. Координаты появления игрока и врагов задаются метаданными в координатах тайлов (столбец, строка); спавн игрока обязателен, для врагов задаются одна или несколько точек. Символы сетки:

| Символ | Значение | Проходимость |
|---|---|---|
| `.` | Пусто | Проходимо |
| `#` | Кирпич | Препятствие, разрушается поквадрантно |
| `@` | Сталь | Препятствие для танков; обычные пули поглощаются, пули игрока уровня 3 разрушают тайл после попадания |
| `~` | Вода | Препятствие для танков, пули пролетают |
| `*` | Лес | Проходимо; рисуется поверх танков и пуль, скрывая их до выхода из леса |
| `=` | Лёд | Проходимо, скольжение |
| `E` | База | Ровно 2×2 клетки, иначе ошибка валидации |

Пример сетки (иллюстративный, не финальный контент):

```
.............
..###...###..
..###...###..
.............
.##.@@.@@.##.
.##.@@.@@.##.
.............
..###...###..
..###...###..
..##.....##..
.....####....
.....#EE#....
.....#EE#....
```

Метаданные уровня: номер, состав ровно из 20 врагов (код типа для каждого), обязательная точка появления игрока, одна или несколько точек появления врагов, номер фона/палитры, задержка между появлениями. Координата спавна — тайл сетки, являющийся левым верхним углом занимаемого танком квадрата 16×16 px; так как танк занимает один тайл, дополнительное центрирование не требуется. Позиция базы задаётся только сеткой `E`.

Правила валидации: ровно 13 строк по 13 символов; только допустимые символы; ровно четыре `E`, образующие квадрат 2×2; обязательная точка появления игрока и минимум одна точка появления врагов; состав ровно из 20 записей; точки появления заданы координатами верхнего левого тайла танка, находятся внутри поля, не пересекаются с базой, друг с другом и с тайлами, непроходимыми для танка.

## Приложение Г. Чек-лист приёмки

- [ ] Игра запускается и показывает меню.
- [ ] Все встроенные уровни проходятся до победы.
- [ ] Разрушение базы приводит к поражению.
- [ ] Потеря всех жизней приводит к экрану «игра окончена».
- [ ] Каждый бонус проверен по семантике: мгновенные эффекты применяются один раз, временные истекают, постоянные сохраняются до своего условия сброса.
- [ ] Танк не застревает в проходах шириной в один тайл.
- [ ] Обычные пули останавливаются о сталь; пуля игрока уровня 3 разрушает стальной тайл и проходит дальше.
- [ ] Пауза останавливает игру и возвращает в неё.
- [ ] Прогресс и рекорды сохраняются после перезагрузки.
- [ ] Звук включается после первого действия пользователя.
- [ ] Изображение корректно масштабируется при разных размерах окна.
- [ ] На целевом ПК (Windows 10/11, актуальный Chrome или Edge, 1920×1080) 10-минутный прогон удерживает среднюю частоту логики не ниже 58 шагов/с и среднюю частоту рендера не ниже 58 кадров/с, без падения любой из них ниже 50/с дольше 1 секунды.
